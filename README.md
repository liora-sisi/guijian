# 归笺

<p align="center"><img src="assets/guijian-cover.png" width="360" alt="归笺：折成小舟的信笺沿着归途回家"></p>

> LIORA × ELION · 让每一段对话，都有归处。

一个本地优先的浏览器扩展，用来保存当前 AI 对话页、自动续记新消息，并在用户明确点击后低速上翻补齐旧记录。

它只处理你当前打开并有权访问的页面，不读取登录凭据，不调用隐藏接口，不枚举其他房间，也不会把对话发送到网络。

当前版本：`0.6.3`

## 适合什么场景

- 平时打开对话页时，自动记录当前已加载内容和随后出现的新消息；
- 手机聊过、网页端尚未加载旧内容时，手动点击一次“补齐旧记录（上翻）”；
- 长房间中断后继续接续，避免每次从头重新保存；
- 在本地档案柜里搜索房间、查看缺口状态，并按用途导出 JSON、Markdown 或纯文本；
- 为之后的阅读副本、知识整理或其他个人工具保留可校验的原始档案。

## 平台兼容状态

| 平台 | 当前状态 | 已确认范围 |
| --- | --- | --- |
| Kimi | 已实测 | 专用消息区识别、自动续记和手动回溯；网页档案标记为当前网页主来源 |
| ChatGPT | 已实测 | 专用角色属性识别、自动续记和手动回溯；网页档案标记为等待官方导出确认 |
| DeepSeek | 已实测 | 通用结构学习、自动续记、手动回溯和角色锚点；已完成小样本现场核对 |
| Claude、Gemini、腾讯元宝、豆包、千问 | 实验性候选，尚未实测 | 仅确认归笺会在这些域名加载；首次可能需要“认领一条消息”，不保证自动续记、角色、思考区、长房间或到顶判断正确 |

白名单只表示扩展获准在该网站运行，**不等于已经通过兼容验证**。未实测平台应先用短而不重要的房间验证，导出后检查消息数量、角色、首尾内容、分段和缺口，再决定是否处理长房间。

尤其是 Claude：目前没有专用适配器，也没有现场样本。按现有通用兜底机制推测，手动认领消息区后可能可以回溯，但它也可能出现自动随行不启动、角色误判、流式尾部重复或虚拟列表漏段等问题；在完成真实小样本核对前，项目不会宣称“支持 Claude”。

## 工作方式

### 自动随行

打开已识别的 AI 对话页后，扩展会保存当前已加载内容，并监听该消息区之后新增或流式完成的消息。自动随行不会自行滚动，也不会打开或枚举其他房间。

### 补齐旧记录

只有用户点击“补齐旧记录（上翻）”后，扩展才会在当前房间低速上翻。运行中持续保存检查点；消息区重建或暂时异常时最多自动接续 15 次，完成或停止后恢复自动随行。

### 本地档案柜

点击浏览器工具栏里的扩展图标，可以查看：

- 总房间数、最新消息总数和今日新增；
- 按平台汇总及每房最后入档时间；
- 分段、缺口和到顶证据；
- 本地标题/正文搜索；
- 逐房导出、全部最新档案导出，并记住上次选择的下载格式；
- 需要二次确认的逐房删除。

## 安装

目前采用“加载解压缩的扩展”方式：

1. 下载仓库源码并解压；
2. 在 Edge 打开 `edge://extensions/`，或在 Chrome 打开 `chrome://extensions/`；
3. 开启“开发人员模式”；
4. 点击“加载解压缩的扩展”，选择包含 `manifest.json` 的仓库目录；
5. 刷新已经打开的 AI 对话页。

网页右侧会出现一个可上下拖动的小圆点。绿色表示自动随行，蓝色表示正在补档，灰色表示尚未识别消息区。

展开小圆点后，可在“导出格式”中直接选择 JSON、Markdown 或 TXT，再点“按所选格式导出本房”。工具栏里的本地档案柜会把“本次导出格式”直接显示在主界面，不必先打开设置；逐房与全部最新房间都会采用当前选中的格式。

## 第一次使用

1. 先选一个短且不重要的房间；
2. 刷新页面，观察小圆点是否变绿；
3. 若保持灰色，展开面板，点“指定一条消息”，再点任意一条完整消息；
4. 需要历史内容时，再点“补齐旧记录（上翻）”；
5. 到顶后先导出本房 JSON，核对消息数、分段和缺口；需要直接阅读时，再在档案柜的设置中选择 Markdown 或纯文本。

不要同时启动多个自动滚动脚本。其他只读存档扩展可以用于交叉核验，但不同工具的档案不会自动合并。

## 数据与完整性

### 三种下载格式

- **JSON**：完整保存 `manifest`、`raw` 和 `normalized`，适合校验、程序处理以及未来接入 Echo；
- **Markdown**：按房间和消息排版，适合阅读、做笔记或继续整理；
- **纯文本 TXT**：不依赖 Markdown 阅读器，适合直接打开、全文搜索和分享自己的授权资料。

Markdown 和 TXT 是从规范化层即时生成的阅读副本，不会修改或覆盖浏览器里的原始档案。它们会分别标注网页提供的对话时间与归笺首次抓取时间；网页没有时间时，会明确写“网页未提供”，不会拿抓取时间冒充对话时间。

每个 JSON 同时包含：

- `manifest`：房间编号、快照继承链、条数、顺序哈希和完整性证据；
- `raw`：不可被清洁层覆盖的原始分段；
- `normalized`：角色、清洁正文、单独思考区、时间证据和内容哈希。

工具不会做危险的全局内容去重。不同位置重复说“好的”会被保留；只有相邻窗口存在顺序证据时才合并。没有重叠的窗口会保留为不同分段并写入缺口警告。

“页面稳定到顶”是强页面证据，不等于证明平台服务器端绝对完整。ChatGPT 等提供官方导出的平台，正式长期归档仍应以官方数据包为权威来源，网页档案适合作为及时补充。

## 时间说明

- 页面提供原始时间元数据时，单独保存为平台时间候选；
- 页面没有原始时间时，只记录首次观察时间和“最晚不晚于此”的上界；
- 抓取时间不会被伪装成消息实际发生时间。

## 隐私与权限

- 所有档案保存在浏览器扩展的本地 IndexedDB；
- 无遥测、无远程服务器、无网络上传；
- 不读取 Cookie、令牌、认证头、密码或验证码；
- 不绕过登录、访问控制、验证码或平台风控；
- 只应保存你本人有权访问的数据。
